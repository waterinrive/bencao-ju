# 本草·局 产品说明计划书

> 一句话：**BOSS=病证、卡牌=中药、组方=出牌**——一款让人在打牌中自然学会「君臣佐使」与「七情配伍」的中医方剂学卡牌策略游戏，关卡由知乎站内真实内容 AI 生成。

## 一、创作思路

**要解的题。** 方剂学是典型的"背得出、用不出"：书上君臣佐使四条定义人人会背，面对一个病证仍然组不出一剂方。知识停在"认得"，没到"会用"。我们要做的不是又一本交互教材，而是把"辨证论治的决策过程"变成游戏的核心动词。

**核心隐喻。** 病证是 BOSS（要解决的问题），中药是卡牌（手里的工具），组方是出牌（给出的解法）。君臣佐使四个角色位就是四个出牌槽：力专主攻者为君、同类助力者为臣、治兼证减毒者为佐、引经调和者为使；七情配伍化为牌与牌之间的连线——相须金色增效 ×1.5，相反红色中毒。规则即医理，玩懂了规则就玩懂了医理。

**认知闭环。** 看证（八纲/主证/兼证/归经）→ 选药 → 入位 → 结算 → 反馈。结算不是打个分完事：效/险/雅三维评分加逐条评语（"君『麻黄』对主证『发汗解表』✓""兼证『咳喘』未治，每回合反伤"），每一次出牌都是一次辨证推理的练习与纠错。

**教学设计。** 9 步引导关用门控+高亮+里程碑反馈手把手过一遍麻黄汤；结尾「换君试错」让玩家亲手摆一剂桂枝为君的方，对比 18 伤与 15 伤、反伤 3 与 0——"换君=换治法"不讲而自明。教学关纯前端可玩，4 分钟从零基础到独立组方。

**内容观。** 每张卡牌是结构化知识资产（主/副功效、四气五味、归经、配伍七情、毒性、心力成本），不是贴图；全部数据开放在仓库 JSON 中，可审计、可贡献、可复用。

## 二、技术方案

- **架构**：React 单屏棋盘（战报/棋盘/诊断三区、浮层四角归位）+ Hono 单进程后端（静态托管与 API 同进程）+ `shared/` 纯 TS 引擎前后端同跑，Docker 单镜像一键部署。
- **规则引擎**：`combat.ts` 结算（位序系数、七情连线、毒性反伤、归经引经、兼证恶化意图），`deck.ts` 回合/心力/弃换；15 条自检用例随 `npm test` 跑，规则改动先过测试。
- **数据契约**：治法/功效/八纲/意图/归经全部受控词表（`enums.ts`），AI 生成与战斗结算读同一份契约—— hallucination 的词进不了游戏。
- **AI 生成管线（wow 点①"这关怎么来的"）**：证型主题池按日期轮转 → **知乎站内搜索**取真实医案/病证内容 → **知乎直答**提取病机生成 BOSS 卡 → 三重校验（词表/难度/自洽）后发布；每张 BOSS 带生成日志（源内容标题、作者、模型、时间戳），玩家可一键查看来源。
- **太医院 mentor（wow 点②）**：组方后点「问」，直答基于受控词表给方向点拨，不直接给答案。
- **体验工程**：触屏首点抬牌看全貌+详情、再点打出；卡面贴纸自动化裁标签管线；headless 截图自查（`scripts/shot.mjs`）与演示录像（`demo-video.mjs`）进开发流程。
- **降级策略**：知乎 API 不可用时 BOSS 回落内置病证库、mentor 提示不可达，教学关零网络依赖——demo 永远打得开。

## 三、适配知乎社区的场景价值（重点）

1. **已真实接入，而非概念演示**：站内搜索、直答、黑客松 content API 三类能力全部跑在主玩法里（BOSS 生成/mentor/典故源），并做了额度与降级设计。本作是"知乎开放能力 × 游戏化"的完整参考实现。
2. **把「问答」变成「关卡」的通用通路**：知乎沉淀了全网最密的结构化知识回答/文章（中医医案只是其一）。本作验证的管线——社区内容 → 受控词表 → 可玩关卡——今天生成病证 BOSS，明天就能生成法条关、史实关、编程坑关。游戏是社区内容的第二种消费形态。
3. **日活钩子与创作者回流**：「今日病证」按日轮转、源自站内内容，玩家每天回来打新关；生成日志把源回答/文章作者署名回链——创作者第一次被"关卡引用"，社区内容获得游戏化分发与署名激励。
4. **科普与校园场景载体**：教学关本身就是一篇 4 分钟可玩的互动科普，可嵌入科普专栏、校园活动、答题场景；卡牌库开放 JSON，社区可共建药材/方剂/病证（PR 式贡献），UGC 有天然抓手。
5. **天然讨论体质**：效/险/雅三维评分与逐条评语是现成的讨论引子（"我这方为什么只评及格？""桂枝为君到底行不行"），契合知乎的评论/回答文化——每一局结算都可以是一篇回答的开头。
